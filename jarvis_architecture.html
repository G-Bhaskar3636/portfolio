Jarvis DataScience — system architecture

agentic desktop assistant

Jarvis is the most structurally complex of my projects, so it gets its own diagram. It's a single Streamlit app with five independent subsystems — a command router, an agentic core, capability modules, a dual-memory layer, and one external LLM provider — all wired together through a shared tool registry.

  1. Command routing. The user types or speaks in the Streamlit UI; command_pipeline.py catches the request first.
  2. Intent classification. system_intent.py decides whether it's a chat query, a dataset action, a vision request, or a voice command, and routes accordingly.
  3. Agentic chat. Chat queries go to agent_graph.py, which pulls context from both memory stores, decides whether to call a tool via tool_registry.py, then calls Groq Cloud through llm.py.
  4. Dataset requests run entirely inside dataset_studio.py — profiling, cleaning, and AutoML with Scikit-learn — and only touch the LLM for natural-language transform commands.
  5. Voice input passes through vad.py (explicit start/stop, no continuous listening) into stt.py (local Faster-Whisper), then re-enters the same command pipeline as text; replies return via tts.py.
  6. Memory write-back. Every conversational turn is persisted to chroma_agent_memory.py so later turns in the same session can recall it.
